# Crawl4AI版で現在できること

2026-11-15 JST。現状は、MCP対応のAIクライアントから我孫子市の資料を調べるためのローカルツール。Crawl4AI専用の取得・検索・出典参照を使える。幅広い質問に自動で回答する完成サービスには達していない。[14問の試用](trial-results.md)では生活案内と一部の審議内容に到達したが、回答品質・網羅性の正式な評価は行っていない。

## 中心にする市民の質問

利用者は資料名や議案番号を知らない市民。「子育て関連で最近議論されているのは何か」「どんな要望が上がっているか」「どこから要望を伝えられ、それがどう扱われたか」を主なユースケースに置く。

| 目標とする調査 | 現状 |
|---|---|
| 最近の子育ての議論を、場・争点・市の答弁・決定/未決に分けて整理 | 未評価。2024年中心の選定資料では最近の議論を検証できない。会議録本文等の収集が必要 |
| 市民の要望を公開資料から横断して整理 | 未評価。要望を公開した資料群の収集と、直接の意見/議員等の紹介の区別が必要 |
| 行政・議会・意見募集等の参加経路を比較 | 公式案内4ページの所在確認とMCP取得・参照は確認。一連の市民向け回答は未評価 |
| 要望がどこまで議論・対応に反映されたか追跡 | 未評価。個別要望と会議録・判断・対応を結ぶ根拠の調査が必要 |

[市民向け調査の仕様](citizen-research.md) に、対象期間、必要な資料、回答の形、反映を論じる際のルールをまとめた。ここで挙げる目標は、現在すでに回答品質を満たしている能力の一覧ではない。

## 使う流れ

市のトップやカテゴリーを `discover_links` で読む→クライアントが資料のURLを選ぶ→`fetch_document` で保存→語句を分けて `search_documents` で検索→`read_source` で根拠と期間を確認する。表の配置・画像PDFは `render_pdf_page` で原本を見る。

自然言語の質問を解釈し、次のURL・検索語を選び、最終回答を書くのは接続したAIクライアント。サーバー内にLLM、質問の自動分解、独自のチャットUIは実装していない。検索は語句のANDであり、意味検索ではない。

## 取得基盤で確認済みの下位機能

| 調べたいこと | 現在できる範囲 | 必要な確認・限界 |
|---|---|---|
| 転入届の期限・届出人 | 掲載HTMLを取得し、14日以内・本人/同一世帯員等の根拠を検索・参照 | 特例転入など条件の違う案内を区別 |
| ごみの分別・手数料 | 落ち葉・雑草の分別、PDF発行後の訂正を掲載HTMLで確認 | 古いPDFだけで現在の扱いを答えない |
| 児童手当の対象・金額 | 対象年齢・支給日、HTML表の高校生年代の第1/第2子月額を参照 | 人数や年齢に応じた列対応を原文で確認 |
| 防災の一般案内 | 警戒レベル4の名称・求める行動を参照 | 現在の発令・開設状況を示すものではない |
| 過去議会の会期・議案・質問要項 | 2024年6月会期をリンクで探し、予定・提出議案・質問内容を別資料で確認 | 質問要項は市の答弁や実施済みの証拠ではない |
| 過去議会の採決結果 | 採決PDFの賛否人数を参照し、議員別賛否は原本画像を表示 | 特定議員と○/×の列対応はテキストだけで確定しない |
| 予算・施政方針・総合計画 | 2024年度の当初/補正予算、施政方針、2022～2033年度の基本構想を検索・参照 | 予算成立と執行、方針と実施、年度の違いを混同しない |
| 画像PDF・古い資料 | 原本の特定ページをMCPから画像表示 | OCR・本文検索は不可。画像を読むクライアントが必要 |
| 市の実際の答弁を横断調査 | 外部会議録サイトの一覧画面までは取得 | 会議録本文の収集・検索は未実装 |

上表は資料の取得・抽出・検索・参照を確かめた下位の例。議案番号などを知っている前提の検証を、市民向け調査の完成度に置き換えない。市の全ページ、全会期、任意の質問へ一般化しない。

実サイトの技術検証では、20資料のAPI応答、16質問の検索・原文確認（画像PDFを除く15/16到達）、追加2質問、6段階のリンク発見、原本2ページの画像取得を確認した。画像PDFのAPI成功は本文取得成功に数えない。実行結果と原本はローカルの検証記録として扱い、公開リポジトリには含めない。

## 出典と保存

各版にURL・取得日時・原本ハッシュを保持し、PDFには物理ページ番号を付ける。対象年度・会議日・資料の性格は、選定20資料のレビュー済みcatalogで確定した値。未知URLでは `unclassified` と日時候補を返し、自動で確定しない。

保存本文の検索はローカルのみ。最新取得が失敗した場合に、古い成功版へ黙って戻らない。過去版はそのIDで読める。原本補助抽出を検索対象の本文へ混ぜない。

## まだ実装していないこと

全体の網羅巡回・更新/削除の検知、未収集資料を含む検索、外部会議録本文、OCR、複雑な表の自動構造化、未知資料の年度・会議日・資料種別の確定、任意のAIクライアントの回答品質保証。常設の利用者向け画面、多数同時利用、定期収集の運用もない。

## 確認コマンド

`just smoke` は実サイトの転入届・議会入口・採決PDFをMCP経由で取得し、検索・原文参照・リンク発見まで通す。`just bench` は20資料を取得して選定16質問の根拠包含とtop5到達を確認する。`just details` は予算明細と児童手当表の追加2質問を確認する。これらは任意のLLMの回答正解率の試験ではない。
