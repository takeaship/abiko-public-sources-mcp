# 市民の関心から、市政の議論と要望の扱いを調べる

2026-11-15 JST。利用者は議案番号や資料名を知らない市民。目標は「最近の子育ての議論は何か」「どんな要望があり、どう伝えられ、どう扱われたか」を、複数の公開資料から出典付きで理解できること。

これは既存ツールの使い道を定め直した仕様と評価方針。4つの市民向け調査シナリオは未評価であり、現在の5ツールがすでに横断調査の回答品質を満たしたという意味ではない。別に行った[14問の探索的な試用](trial-results.md)は、これら4シナリオの正式な評価には置き換えない。

## 主な質問と、回答で示したいもの

| 市民の質問 | 必要な調査 | 回答の形 |
|---|---|---|
| 子育て関連で最近議論されているのは何か | 期間を定め、一般質問・本会議/委員会の会議録を調べる。審議会や計画策定の議論は別に整理 | 話題ごとの争点、誰がどの場でいつ述べたか、市の答弁、決まったこと・未決のこと、根拠と調査範囲 |
| 子育てについて市民からどんな要望が上がっているか | 公開された請願・陳情、パブリックコメント、懇談会の発言・市の回答、調査結果を横断 | 要望の内容、提出/発言経路、時期、市の回答。複数資料に同じ要望が出ても二重計上しない |
| 市民はどこから要望を伝えられるか | 行政向け・議会向け・特定の案への意見募集を分け、最新の受付案内と条件を確認 | 経路ごとの宛先・用途・手続・受付時期・扱いの違い。提出を代行する機能は含めない |
| その要望は、どの程度議会の議論に反映されているか | 公開された個別要望から、議会での扱い、答弁、採決、対応状況を追う。議案や予算資料だけで因果を作らない | 要望ごとの追跡表。確認できた段階・その出典・対応関係の根拠・分からない範囲 |

最初の対象テーマは子育てとする。保育・学童・給食・教育・医療費などの関連語への展開は調べる側の仕事であり、利用者に正解語句や議案番号の入力を求めない。実際に見つかった話題を整理し、あらかじめ決めた話題数へ合わせない。

「最近」は、初期評価では実行日を基準とした直近12か月を既定案に置く。これは実装済みの期間フィルターでも、利用者が確定した条件でもない。質問に期間があればそれを優先し、回答に基準日・対象期間・取得済み/未取得の範囲を表示する。古い経緯を読む場合は、期間内の話題と背景資料を分ける。

## 要望の経路を分ける

公式案内で確認した資料は次のとおり。経路が存在することと、提出された要望の全件が公開されることは別である。

| 経路 | 確認した公開資料 | 調査で注意すること |
|---|---|---|
| 行政へ伝える | [市政への意見・要望のFAQ](https://www.city.abiko.chiba.jp/kurashi/faq/shisei/shiminsoudan/iken.html)：市政へのメール・手紙、封書・FAXの案内 | 市の担当課や市長への意見・回答を、議会の審議・決定と同一視しない |
| 議会へ伝える | [請願・陳情の提出方法](https://www.city.abiko.chiba.jp/shisei/shigikai/shimin_shigikai.html) | 紹介議員や提出方法・内容によって扱いが異なる。提出した要望がすべて同じように議題になるとは説明しない |
| 対話の場で伝える | [市政ふれあい懇談会](https://www.city.abiko.chiba.jp/shisei/shisei_sanka/fureaikondankai.html)：開催案内・過去の要旨・市の回答への入口 | 市長との意見交換を議会の議論と混同しない。参加できる日時・場所は都度確認する |
| 特定の案に意見を出す | [パブリックコメント制度](https://www.city.abiko.chiba.jp/shisei/shisei_sanka/publiccomment/index.html)：手続・提出意見と市の考え方への入口 | 意見募集の対象と期間を確認し、市の考え方や案の修正を追う。議会で扱われたことは別に確認する |

これら4ページはCrawl4AI版MCPでも取得・参照した。経路の存在確認と、市民の質問から条件を整理して回答する評価は別に扱う。個別要望と議会の記録・行政の対応を明示的な根拠で結ぶ、継続した追跡はまだ必要である。

## 「反映」を一つの状態にしない

以下は調査で区別する段階であり、どの経路も同じ順番で進むわけではない。行政へのメール、パブリックコメント、懇談会発言が自動的に議会へ送られるという意味ではない。

| 確認したいこと | 必要な根拠の例 | それだけでは言えないこと |
|---|---|---|
| 意見・要望が公開されている | 請願・陳情の内容、意見と市の考え方、懇談会要旨 | 市民全体の意見、未公開要望を含む総数 |
| 正式な受付・扱いが分かる | 請願・陳情番号、受理・付託・参考配布等の記録 | すべてが委員会の審査対象になったこと |
| 議会で扱われた | 本会議/委員会の会議録と、当該要望への明示的な言及 | 要望を受けて議論したという因果、要望が実現したこと |
| 議会の判断がある | 当該案件の採択・不採択・継続審査等の記録 | 採択された内容が実施されたこと |
| 行政の対応がある | 処理経過・結果、市の回答、計画の修正理由等 | 市の回答が議会の決定であること |
| 予算・施策・実施との関係が分かる | 要望との対応を明示する資料、予算、実施報告 | 予算成立だけで実施済みとすること、同じ話題が後から出ただけで要望の効果とすること |

回答の追跡表には「要望の内容/経路/日時」「扱われた場と日時」「確認できた対応」「対応関係の根拠」「原文」「未確認」を並べる。議会の委員会と、子ども・子育て会議などの審議会は、開催主体・場の種別を分けて表示する。

対応関係は、資料に明示された関係、同じテーマだが関係を確認できないもの、資料不足で不明なものを分ける。記録が見つからないことを「取り上げられなかった」「無視された」と言い換えない。議員が紹介した住民の声は、その発言者による紹介として示し、直接公開された市民の意見と区別する。

割合を示す場合は、母集団・期間・重複の扱い・対象件数と、分子に何を数えたかを先に示す。公開された一部の要望しか確認できなければ、市民の要望全体の「反映率」を出さない。数字が裏付けられない場合は、追跡できた事例と分からない範囲を示す。

## 評価の変更

[市民向けシナリオ](../evaluation/citizen-scenarios.json) を今後の主たる受入評価にする。正解資料名・URL・検索語を利用者の質問へ埋め込まず、複数の資料から調べる。評価前に、対象期間の原文を人が確認して参照資料一式を用意し、期待する論点・出典・対応関係・限界を決める。

既存の `questions.json` / `followup-questions.json` は資料取得・PDF抽出・検索・出典参照の技術的な回帰試験として残す。「議案第8号は可決されたか」への到達は有用な部品検査だが、市民向けの横断調査が完成した証拠にはしない。

主に評価するのは、期間内の主要論点を落としていないか、複数の場・立場を区別したか、市民の声と議員の発言を区別したか、根拠をたどれるか、要望と対応の関係を過大に推測していないか、調査の不足を示せるか。API成功率と語句一致だけで合格を決めない。
